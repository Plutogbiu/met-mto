| 项目 | 内容 |

## 2. 迭代目标

围绕 v1.2 已沉淀的工单、打卡和附件数据，增加报告输出和管理分析能力，减少人工整理工作。AI 总结作为可控的辅助能力，先保证数据和人工总结流程可用，不把核心业务依赖在 AI 服务上。

## 3. 需求范围

### 3.1 工单回执报告 PDF 导出

第一阶段只做后台工单详情中的单条导出，不做客户详情历史工单批量导出。当前先使用系统基础模板，最终正式模板确定后再调整排版。已完成工单详情提供“导出回执 PDF”入口，按工单生成 PDF 并下载，报告内容包括：

1. 工单编号、工单类型。
2. 创建时间、完成时间。
3. 客户名称、客户地址。
4. 设备信息。
5. 维保类型。
6. 工单内容。
7. 工单创建人。
8. 指派工程师。
9. 现场图片和回执图片。
10. 报告生成时间。

维保类型在 PDF 中统一使用中文文案，例如“保内免费”，不直接展示 `warranty_free` 等系统代码。

文件名格式：

```text
物链易通-客户名称-工单类型-创建时间_工单编号.pdf
```

由于 Windows 文件名不能使用冒号，创建时间使用 `yyyyMMddHHmmss` 格式，例如：

```text
物链易通-汇隆煤矿-现场工单-20260727153000_WO202607271530001234.pdf
```

批量导出入口位于后台“工单管理”，不在客户详情页增加导出功能。默认列表不显示勾选框；点击“批量导出”后进入选择模式，仅已完成工单可勾选导出。表头全选仅选择当前页已完成工单，多分页勾选会保留已选状态。单次最多导出 200 条，超出时要求减少勾选数量。

批量导出采用异步 ZIP 任务：

1. 后端单线程逐份生成 PDF，避免 2G 服务器并发渲染大量图片导致内存峰值。
2. 任务状态为排队中、生成中、已完成、生成失败、文件已过期。
3. 单个工单失败只记录失败原因，不中断其他工单的 PDF 和 ZIP 生成。
4. ZIP 放入私有 `exports` 目录，只能通过鉴权接口下载。
5. 文件默认保留 24 小时，定时清理已过期 ZIP 和临时文件。
6. 同时只处理 1 个任务，等待队列最多保留 2 个任务。

PDF 中文字体作为部署资源放在后端运行目录的 `fonts` 文件夹，通过 `mto.pdf.font-path` 配置指定；不依赖 Windows 或 Linux 的系统字体路径。

回执图片区允许跨页展示，但单张图片及其分类说明不得被拆分到两页。PDF 导出时只对嵌入报告的图片执行缩放和标准 JPEG 重编码，默认最大边长为 `1600px`、压缩质量为 `0.82`；不修改系统中保存的原始附件。

### 3.2 后台数据分析看板

新增后台数据分析页面，仅对具有看板权限的用户开放。第一阶段使用实时聚合查询，不新增统计快照表；本次仅实现以下两个看板：

1. 顶部核心指标：工单总数、待处理、处理中、已完成、已作废数量及完成率（已完成 / 工单总数）。
2. 工单趋势：展示工单每日创建数量和每日完成数量；日期范围不超过 31 天按日聚合，31 至 180 天按周聚合，超过 180 天按月聚合。
3. 客户工单数量 Top 10：按工单创建时间统计客户工单数，用于识别近期问题集中煤矿；点击客户后跳转工单管理，并自动携带客户、工单类型和日期范围筛选。
4. 支持“全部工单、现场工单、日常巡检”类型筛选，筛选条件同时作用于核心指标、趋势和客户 Top 10；支持刷新和空数据状态，默认范围为当前月 1 日至当天。

统计范围以工单创建时间为准，状态数量展示所选范围内工单的当前状态。工程师排行、趋势、类型对比等内容保留为后续迭代需求。

管理员和线上运维按权限查看；现场实施工程师不登录后台，也不开放后台看板。

### 3.3 AI 生成个人月度总结

根据指定工程师在指定月份已完成的工单生成月度工作总结草稿，首期只处理结构化工单数据，不默认把现场图片发送给 AI：

1. 输入月份和工程师，默认当前登录用户和当前月份。
2. 汇总完成数量、工单类型、客户分布、设备/问题内容和处理内容。
3. 生成可预览、可编辑、可复制的总结草稿。
4. AI 不直接修改工单、不直接发布总结，用户确认后再使用文本。
5. AI 不可用时，返回基于模板的统计总结，不影响工单和看板。
6. 服务商、模型、费用和数据出境策略在开发前确认，密钥通过配置注入。

首期不做图片视觉分析、自动判断维修结论、自动修改工单、自动发送客户和复杂知识库问答。

### 3.4 待定需求

1. PDF 最终模板及是否生成后归档。
2. 煤矿负责人签字的最终来源和文件格式。
3. AI 服务商、模型、调用额度和总结审核流程。
4. 是否增加看板导出 Excel/PDF。

## 4. 初步接口规划

以下为规划接口，开发前可根据页面调整，当前不代表已实现：

| 功能 | 接口规划 |
| --- | --- |
| 导出工单回执 PDF | `GET /api/admin/work-orders/{id}/receipt-pdf` |
| 创建批量导出任务 | `POST /api/admin/work-orders/export-tasks` |
| 查询批量导出进度 | `GET /api/admin/work-orders/export-tasks/{taskId}` |
| 下载批量导出 ZIP | `GET /api/admin/work-orders/export-tasks/{taskId}/download` |
| 查询看板汇总 | `GET /api/admin/dashboard/overview` |
| 查询看板趋势 | `GET /api/admin/dashboard/trends` |
| 生成个人月度总结 | `POST /api/admin/work-summary/generate` |

## 5. 数据库规划

本阶段数据库变更：

1. 单条 PDF 优先实时生成，不新增单份报告归档表。
2. 批量导出新增 `work_order_export_task` 和 `work_order_export_item`，记录任务状态、明细、失败原因和 ZIP 私有路径。
3. 看板使用现有工单、指派、打卡和附件表聚合查询，不新增统计快照表。
4. AI 总结先返回草稿，不默认保存历史版本。

## 6. 权限规划

正式开发时增加可独立分配的权限项：

1. `dashboard:view`：查看数据分析看板。
2. `work-order:receipt-export`：导出工单回执 PDF。
3. `work-order:receipt-batch-export`：创建、查看和下载批量回执 ZIP。
4. `work-summary:generate`：生成个人月度总结。

新增权限时同步维护权限枚举、`data.sql` 默认权限和后台权限分配页面，不直接把权限硬编码到某个角色。

## 7. 验收标准草案

1. 已完成工单可从后台详情导出可打开的 PDF，内容与工单详情一致。
2. PDF 附件按工单类型和附件分类展示，缺少某类附件时正常生成。
3. 工单管理进入批量导出模式后仅允许勾选已完成工单；勾选和多分页选择均受 200 条上限保护。
4. 批量导出以异步 ZIP 任务执行，页面可查询成功数、失败数和下载状态。
5. ZIP 下载必须校验批量导出权限和任务创建人；管理员可以查看全部任务。
6. 看板指定日期范围统计正确，刷新后能看到新数据。
7. 看板遵守现有权限规则。
8. 月度总结可按工程师和月份生成，可编辑；AI 不可用时仍有模板总结。
9. AI 失败不影响工单、附件和看板接口。

## 8. 开发顺序建议

1. 先确定 PDF 模板和字段映射，再实现 PDF 导出。
2. 再实现看板聚合接口和后台页面。
3. 最后实现 AI 总结，优先具备模板降级能力。
4. 待定需求确认后再决定是否进入 v1.3，避免范围持续膨胀。
